Source     Big Mess o' Wires: read on Windows, 2026. Device and configuration descriptors through

           descriptors reconstructed by hidapi 0.15.0 (hid_get_report_descriptor) from Windows'
           parsed HID data

Notes
  - The report descriptors are reconstructions: functionally equivalent (collections, report IDs,
    field positions, sizes, usages, flags), not byte-identical. Windows doesn't expose raw report
    descriptors, and the hub driver refuses report descriptor requests. Real lengths from the
    configuration descriptor: interface 0 59 bytes, 1 34, 2 181, 3 31 (reconstructed: 66, 34, 183,
    47).
  - Interface 0 is a plain boot keyboard and carries normal typing. Interfaces 1 and 3: vendor
    (64-byte reports). Interface 2: Mouse (report 1), System Control (2), Consumer Control (3),
    vendor (4), keyboard (5) collections, in that order. Windows shows them as COL01-COL05.
  - The interface 2 keyboard is a 232-key bitmap (usages 0-0xE7) declared as an Array instead of a
    Variable: the same Holtek bug as the Mistel MD770 (udev-hid-bpf fixes it by changing that Input
    item to Variable). It presumably carries keys beyond the first 6 held at once. Its first
    collection is a Mouse, although the keyboard has no pointing device.
