Type       Real device
Source     https://github.com/hrvach/deskhop/issues/57

Notes
  - usbhid-dump of the 2.4G receiver. Interface 0 is a mouse (report 3), interface 1 vendor
    (configuration), interface 2 the keyboard: three keyboard collections, report 1 (6-key array,
    boot layout after the ID), reports 12 and 10 (120-key bitmaps), plus consumer (2, 17) and system
    control (6).
  - The wired keyboard is 2dc8:5200 (the 8bdkbd tool's PID; its vendor interface is 2 there, so the
    wired interface order differs from this receiver's). Wired use needs the Mode switch at OFF
    (manual); at 2.4 or BT the keyboard talks only to the receiver or Bluetooth. The Retro 108 is
    2dc8:5209 (receiver 520a), whose interfaces Windows lists as boot mouse / boot keyboard / boot
    mouse.
  - It types on the NKRO bitmap (report 12 or 10; same layout), at least sometimes. A user report: a
    host that decoded the bitmap as a key array typed "m" for Space (usage 2C is bit 4 of report
    byte 7, read as keycode 0x10). Reddit r/8bitdo 187njzt (Nov 2023): at the BitLocker/BIOS prompt
    only some characters appear, and Backspace/Enter/Esc do nothing, wired and through the receiver,
    so it doesn't send boot-format reports in boot protocol either. deskhop's maintainer: "NKRO
    only".
  - It may also type on report 1: deskhop issue #57's analysis explains its jumbled keys by report 1
    reports decoded with the bitmap layout. usb_hid_host: no reports arrive until both the mouse and
    keyboard interfaces are enumerated.
  - Interface subclass/protocol are not in the dump; all set to 0/0 here (every collection has a
    report ID, so none is in the boot format).

Interfaces
  Interface 0: class 03 (HID), subclass 00, protocol 00, endpoint max packet 64 bytes
  Interface 1: class 03 (HID), subclass 00, protocol 00, endpoint max packet 64 bytes
  Interface 2: class 03 (HID), subclass 00, protocol 00, endpoint max packet 64 bytes
